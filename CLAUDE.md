# CLAUDE.md

# Skills

This repo ships the Spec Kit workflow as ten skills under
`.claude/skills/speckit-*/`, generated by the Specify CLI (v1.0.7.dev0) and
tracked in git so every contributor gets the same commands:

`/speckit-constitution`, `/speckit-specify`, `/speckit-clarify`,
`/speckit-plan`, `/speckit-tasks`, `/speckit-analyze`, `/speckit-checklist`,
`/speckit-implement`, `/speckit-converge`, `/speckit-taskstoissues`.

These skill files are **generated, not hand-maintained**. The Specify CLI
records a checksum for each in `.specify/integrations/claude.manifest.json` and
overwrites local edits on refresh — to change behavior, edit the scaffolds in
`.specify/templates/` rather than the skill files.

Supporting Spec Kit state lives in `.specify/`: `templates/` (spec, plan, tasks,
checklist, and constitution scaffolds), `scripts/bash/` (helpers the skills
invoke), and `memory/constitution.md`.

**Prefer these project skills above all others.** When a task could be served by
a `/speckit-*` skill AND by a global, built-in, or plugin skill, always choose
the project skill. Only fall back to a non-project skill when no project skill
fits the task.

Anything else under `.claude/` — settings, personal skills, local agents — is
gitignored and private to each contributor. Do not assume a teammate has it, and
do not rely on it in committed docs or scripts.

# Constitution

`.specify/memory/constitution.md` (v1.0.0) governs how this project is built.
Its five principles are binding: single-guild scope (per
`docs/ADR-001-guild-scope.md`, non-negotiable), layered dependency direction
(`core/` must not import `transports/`), transport parity across Discord, HTTP,
and Socket.io, fail-fast configuration, and the CI gates in
`.github/workflows/ci.yml`. Read it before proposing architectural changes.
